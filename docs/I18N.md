# Internationalization (i18n) Documentation

## Overview

ZK-VOTE supports internationalization for global DAOs. The i18n system provides:
- Multi-language support (English, Spanish, French, German, Arabic)
- RTL (Right-to-Left) support for Arabic
- Pluralization with language-specific rules
- Locale fallback strategy
- Parameter interpolation in translations

## Supported Languages

| Language | Code | RTL | Plural Forms |
|----------|------|-----|--------------|
| English | `en` | No | one, other |
| Spanish | `es` | No | one, other |
| French | `fr` | No | one, other |
| German | `de` | No | one, other |
| Arabic | `ar` | Yes | zero, one, two, few, many, other |

## Architecture

### I18nContext

The `I18nContext` provides the translation context to the application. It includes:

```typescript
interface I18nContextType {
  language: Language;
  setLanguage: (lang: Language) => void;
  dir: "ltr" | "rtl";
  t: (key: string, params?: Record<string, string | number>) => string;
  tPlural: (key: string, count: number, params?: Record<string, string | number>) => string;
}
```

### Translation Function (`t`)

Basic translation with optional parameter interpolation:

```typescript
const { t } = useTranslation();

// Simple translation
t("vote.button") // "Vote Now"

// With parameters
t("dao.member_one") // "member"
```

### Pluralization Function (`tPlural`)

Handles pluralization based on language-specific rules:

```typescript
const { tPlural } = useTranslation();

// English: singular
tPlural("dao.member", 1) // "member"

// English: plural
tPlural("dao.member", 5) // "members"

// Arabic: complex pluralization
tPlural("dao.member", 0) // "أعضاء" (zero)
tPlural("dao.member", 1) // "عضو" (one)
tPlural("dao.member", 2) // "عضوان" (two)
tPlural("dao.member", 5) // "أعضاء" (few)
tPlural("dao.member", 15) // "عضو" (many)
```

## Translation Keys

Translation keys use a dot notation for namespacing:

```
nav.browse
nav.publicVotes
nav.docs
vote.button
vote.cast
home.hero.title
home.hero.description
dao.member_one
dao.member_other
```

### Pluralization Keys

For pluralization, use the pattern `{key}_{form}`:

```
dao.member_one    // singular form
dao.member_other  // plural form (en, es, fr, de)
dao.member_zero   // zero form (ar)
dao.member_two    // dual form (ar)
dao.member_few    // few form (ar)
dao.member_many   // many form (ar)
```

## RTL Support

RTL (Right-to-Left) support is automatically applied for Arabic. The `dir` attribute is set on the document element:

```typescript
const { dir } = useTranslation(); // "ltr" or "rtl"
```

The direction is automatically applied to the document:
```html
<html dir="rtl" lang="ar">
```

## Fallback Strategy

The i18n system implements a robust fallback strategy:

1. **Primary**: Look for the key in the current language
2. **Secondary**: Fall back to English if the key ismissing
3. **Tertiary**: Return the key itself if not found in English

```typescript
// If "vote.button" is missing in Spanish:
t("vote.button") // Falls back to English: "Vote Now"

// If key doesn't exist in any language:
t("nonexistent.key") // Returns: "nonexistent.key"
```

## Adding a New Language

### 1. Create the locale file

Create a new JSON file in `frontend/src/i18n/locales/`:

```json
{
  "nav.browse": "...",
  "nav.publicVotes": "...",
  // ... all required keys
}
```

### 2. Update I18nContext

Add the import and update the type:

```typescript
import ja from "./locales/ja.json";

export type Language = "en" | "es" | "fr" | "ar" | "de" | "ja";

const translations: Record<Language, Record<string, string>> = {
  en, es, fr, ar, de, ja,
};
```

### 3. Update RTL languages (if needed)

```typescript
const RTL_LANGUAGES = new Set(["ar", "he", "fa", "ur", "ja"]);
```

### 4. Update pluralization rules

Add language-specific pluralization in `getPluralForm`:

```typescript
function getPluralForm(lang: Language, count: number): string {
  if (lang === "ja") {
    // Japanese has no pluralization
    return "other";
  }
  // ... existing rules
}
```

### 5. Update LanguageSwitcher

Add the new language to the language list:

```typescript
const LANGUAGES: { code: Language; name: string; flag: string }[] = [
  // ... existing languages
  { code: "ja", name: "日本語", flag: "🇯🇵" },
];
```

## Usage in Components

### Basic Usage

```typescript
import { useTranslation } from "../i18n/I18nContext";

function MyComponent() {
  const { t } = useTranslation();
  
  return <button>{t("vote.button")}</button>;
}
```

### With Language Switching

```typescript
function MyComponent() {
  const { language, setLanguage, t } = useTranslation();
  
  return (
    <div>
      <p>{t("language.select")}</p>
      <select 
        value={language} 
        onChange={(e) => setLanguage(e.target.value as Language)}
      >
        <option value="en">English</option>
        <option value="es">Español</option>
        {/* ... */}
      </select>
    </div>
  );
}
```

### With Pluralization

```typescript
function MemberCount({ count }: { count: number }) {
  const { tPlural } = useTranslation();
  
  return (
    <p>
      {tPlural("dao.member", count)}: {count}
    </p>
  );
}
```

## Best Practices

1. **Use descriptive keys**: Use dot notation with meaningful namespaces
2. **Keep keys consistent**: Use the same key structure across all locales
3. **Provide all plural forms**: For languages with complex pluralization (Arabic)
4. **Test RTL layouts**: Ensure your UI works correctly in RTL mode
5. **Use parameter interpolation**: For dynamic values in translations
6. **Fallback to English**: Always provide English translations as the fallback
